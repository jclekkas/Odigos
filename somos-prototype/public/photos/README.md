# Photography

Every image on the site is declared once in `src/data/media.manifest.json` and
rendered through the `<Photo>` component. Nothing else in the codebase needs to
change when photography arrives.

Each slot resolves in this order:

1. `file` — a real photo in this folder, e.g. `"file": "home-hero.jpg"`
2. `remote` — a hosted URL, e.g. a CDN or DAM link
3. the generated plate at `plate-<id>.svg` (the current state)

The `plate-*.svg` files are generated by `npm run photos` and are safe to delete
and regenerate. They are deliberately abstract, warm compositions rather than
grey wireframe boxes, so that layout and colour can be reviewed before the shoot.

## Replacing a slot

1. Export the photo at roughly the `ratio` given in the manifest (crop matters
   more than pixel dimensions — the component crops with `object-cover`).
2. Save it here as `<id>.jpg` (or `.webp`).
3. Set `"file": "<id>.jpg"` on that slot, and rewrite `alt` to describe the
   actual photograph.

## What to shoot

The manifest's `subject` field is the shot list. In short: real children at work,
Montessori materials, teachers with individual children, diverse families,
outdoor play, art, language interaction, real classrooms. Avoid posed group
shots and anything that looks like stock photography.

Two rules the copy depends on:

- Only photography taken at a Somos school may be described as a Somos
  classroom, child or teacher in `alt` text or captions.
- Get photo releases for every identifiable child before publishing.
